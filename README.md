# Core V3.0 — Корпоративный аудит

Desktop-приложение для автоматизации аудита розничной сети. Обрабатывает
выгрузки из 1С, АСУС и Тандер Склад: анализ квантов, инвентаризационные
описи, свод ОС/МБП, проверка Брак/Утиль, управление принтерами, работа
с сетевыми папками и встроенный браузер.

## О проекте

**Core V3.0** — внутренний инструмент аудитора розничной сети. Заменяет
ручную обработку Excel-выгрузок из 1С, АСУС и Тандер Склад на
автоматизированные сценарии с валидацией, подсветкой расхождений и
формированием готовых отчётов.

**Область применения:**

- аудит потерь (анализ квантов);
- инвентаризация основных средств и МБП;
- сверка актов списания (Брак/Утиль);
- сборка паллет;
- ведение чек-листов инвентаризации;
- подготовка стандартных комментариев для отчётов.

**Принципы разработки:**

| Принцип | Реализация |
|---------|-----------|
| Логика важнее формы | Работающий код не переписывается ради метрик |
| Данные отделены от кода | Правила хранятся в `JSON`, а не в `Python` |
| Тесты — на логику | Покрытие бизнес-правил, не UI |
| Единый стиль | Только SVG-иконки (Lucide), без эмодзи |
| Тёмная тема | Красный акцент `#D42626`, зелёный — только для успеха |

## Возможности

### Кванты — автоматический анализ потерь

- Загрузка `РТП.xlsx` (реестр товарных позиций) и `Кванты.xlsx`
  (отчёт потерь).
- Фильтрация позиций с потерями ≥ 1000 руб.
- **Три жёстких правила** (применяются первыми, не перезаписываются):
  - **Фрукты/овощи** — типовая причина «Пересорт на кассе»,
    без номера БФ.
  - **Сырьё** (по ГР 20 или по наименованию ТП) — «Потери ТО (сырьё)»,
    без номера БФ.
  - **Местный поставщик** (операции `Приход•Местный` и
    `Приход•Недовоз от поставщика`):
    - Излишек → «Ошибки в работе (Местный поставщик)» + «Нет номера БФ».
    - Недостача → «Потери ТО (Местный поставщик)» + «Нет номера БФ».
- **Мягкие правила** — коробочный недовоз/излишек, зеркальные отклонения,
  хищения.
- Распределение позиций между двумя ревизорами.
- Правила вынесены в `data/kv_rules.json` — изменение без правки кода.
- Экспорт файла `Позиции для РТП.txt` с кодами для выгрузки из Тандер Склад.

### ОС и МБП — свод инвентаризационных описей

- Парсер формы ИНВ-1 (инвентаризационная опись).
- Автоматический поиск строки-шапки по маркеру «количество, шт.».
- Выбор столбца с количеством из двух кандидатов
  («Фактическое наличие» и «По данным бухгалтерского учёта») —
  используется тот, где сумма значений больше нуля.
- Фильтрация служебных строк: шапка, нумерация, итоги.
- Автоподбор ширины колонок в результирующем файле.
- Опция «Убрать лишнее» — фильтр спецодежды, СИЗ и вспомогательных
  позиций. Список в `data/unwanted.json`.

### Брак / Утиль — сверка актов списания

- Сверка двух файлов по номеру документа:
  - «Выборочная проверка актов списания утиля»;
  - «Операции списания».
- Допуск по сумме настраивается (`BRAK_UTIL_TOLERANCE` в `config.json`).
- Подсветка расхождений красным в результирующем Excel.
- Автоподбор ширины колонок.
- Архивирование результата в `.zip`.

### Паллеты — сборка свода

- Обработка папки с файлами `1.xlsx`, `2.xlsx`, … (посменные отчёты).
- Сборка единого свода с расчётом отклонений и суммы.
- Автоподбор ширины колонок.

### Инвентаризация — чек-листы по дням

- Старт новой инвентаризации: ГМ, вариант (А–Ж), дата начала.
- Автокомплит ГМ через `QCompleter`.
- Календарь в стиле приложения — выпадающий, тёмный, с подсветкой
  текущей даты.
- Автоматический расчёт даты окончания по выбранному варианту.
- Чек-лист по дням и сменам с общим прогрессом.
- Debounce-сохранение (300 мс) — снижает частоту записи на диск.
- Смена ГМ и завершение с архивацией.
- Архив инвентаризаций — отдельная вкладка.

### Стандартные комментарии

- Шаблоны хранятся в `data/standard_comments.json`.
- Условные блоки: при отрицательной сумме — «излишек», при
  положительной — «недостача».
- Форматирование сумм в русском формате (`1 234 567,89`),
  процентов (`12,35`).
- Автокомплит ГМ.
- Автоподстановка названия активной инвентаризации.

### Принтеры

- Список установленных через `win32print`.
- Установка по IP: PowerShell + `rundll32` (резервный метод).
- Переименование, установка по умолчанию, проверка доступности.
- Контекстное меню, двойной клик.

### Сетевые папки ГМ

- Поиск ГМ по коду или названию (автокомплит).
- Создание папки ПИ ГМ с пятью подпапками (1–4 сутки, Итоговые).
- Создание ярлыка на рабочем столе через `win32com`
  (резервный метод — PowerShell).

### Расстояние между ГМ

- Расчёт по прямой (`haversine`) и оценка по дорогам (×1.2).
- Кэш координат городов в `data/gm_cities_cache.json`.
- Список магазинов в каждом городе.

### АСУС — встроенный браузер

- `QWebEngineView` с постоянным профилем в `data/webengine/`.
- Cookies, localStorage, IndexedDB сохраняются между сессиями.
- Скачивание файлов через `QWebEngineDownloadRequest` и `QFileDialog`.
- Кнопка «Папка загрузок», счётчик скачанных файлов.
- Горячие клавиши: `F5` — обновить, `Ctrl+H` — на главную,
  `Ctrl+Shift+I` — DevTools.

### Информация

- Инструкция по подготовке файлов для каждого модуля.
- Сведения о программе.
- Кнопка «Скопировать инструкцию».

## Установка

### Требования

- **Операционная система:** Windows 10/11 (проверено на Windows 11).
- **Python:** 3.13 (совместимо с 3.11+).
- **Microsoft Visual C++ Redistributable** (обычно предустановлен).

### Порядок установки

1. **Получение исходного кода:**

   ```bash
   git clone https://github.com/<owner>/core-v3.git
   cd core-v3
   ```

   Альтернативный вариант — скачать архив и распаковать в `C:\Core V3.0\`.

2. **Создание виртуального окружения (рекомендуется):**

   ```bash
   py -3.13 -m venv .venv
   .venv\Scripts\activate
   ```

3. **Установка основных зависимостей:**

   ```bash
   py -3.13 -m pip install -r requirements.txt
   ```

4. **Установка зависимостей для разработки:**

   ```bash
   py -3.13 -m pip install -r requirements-dev.txt
   ```

5. **Запуск приложения:**

   ```bash
   py -3.13 main.py
   ```

### Зависимости

**Основные:**

| Пакет | Назначение |
|-------|-----------|
| `PyQt6` | GUI-фреймворк |
| `PyQt6-WebEngine` | Встроенный браузер АСУС |
| `pandas` | Обработка табличных данных |
| `openpyxl` | Чтение и запись `.xlsx` |
| `xlrd` | Чтение `.xls` |
| `Pillow` | Работа с изображениями |
| `pywin32` | Принтеры, ярлыки, COM |

**Для разработки:**

| Пакет | Назначение |
|-------|-----------|
| `pytest` | Тестирование |
| `pytest-cov` | Покрытие кода |

### Слои приложения

1. **`ui/`** — только пользовательский интерфейс. Бизнес-логика
   отсутствует.
2. **`core/`** — бизнес-логика. Не зависит от PyQt.
3. **`utils/`** — утилиты. Не зависит от PyQt. Полностью тестируемо.
4. **`data/`** — данные в формате JSON. Изменяются без правки кода.

### Работа с потоками

- `BaseFrame.run_in_thread` — запуск фоновой задачи.
- `BaseFrame.run_on_ui` — безопасный вызов UI-функций из фонового
  потока. Реализовано через `pyqtSignal`: Qt автоматически доставляет
  вызов в главный поток.

### Хранение данных

- `DataManager` — singleton, JSON-хранилище с кэшем по `mtime`,
  очередью записи и атомарной записью через `.tmp` + `os.replace`.

## Тесты

Всего **75 тестов**, все проходят. Покрытие — бизнес-логика
(`core/`, `utils/`).

### Запуск

```bash
# Все тесты с подробным выводом
py -3.13 -m pytest tests/ -v

# Быстрый запуск
py -3.13 -m pytest tests/ -q

# С покрытием
py -3.13 -m pytest tests/ --cov=core --cov=utils --cov-report=term-missing

# Один файл
py -3.13 -m pytest tests/test_parsing.py -v

# Один тест
py -3.13 -m pytest tests/test_parsing.py::TestToFloatRu::test_russian_decimal -v
```

### Распределение тестов

| Файл | Тестов | Область |
|------|--------|---------|
| `test_parsing.py` | 32 | `to_float_ru`, `to_float`, `norm_number`, `find_column_ci`, `sum_values` |
| `test_formatting.py` | 10 | `format_number_ru`, `format_percent_ru` |
| `test_data_manager.py` | 7 | запись, кэш, `signature`, повреждённый JSON |
| `test_comments_builder.py` | 8 | условные блоки, `гм_part`, суммы |
| `test_kv_analyzer.py` | 9 | `_load_rules`, правила квантов |
| `test_brak_util_analyzer.py` | 6 | `_safe_filename`, `_fill_columns` |
| **Итого** | **75** | |

### Правила написания тестов

1. Тесты проверяют логику, а не UI.
2. Чистые функции размещаются в `utils/` и `core/` — это делает их
   тестируемыми без `PyQt6`.
3. Общие фикстуры находятся в `conftest.py`. Временные файлы —
   через `tmp_path`.
4. Один тест — один сценарий.
5. Имена тестов описательные: `test_russian_decimal`,
   а не `test_1`.

## Разработка

### Стиль кода

- Type hints — везде, где возможно.
- Docstrings — на каждом модуле, классе и публичном методе.
- Конкретные исключения вместо общего `except Exception`.
- Осмысленное логирование через `utils/logger.py`.
- Магические числа выносятся в константы.
- Дублирование устраняется.
- Разбиение файлов — по принципу единственной ответственности (SRP),
  а не ради метрик.

### Логирование

Логи пишутся в `Logs/core.log` с ротацией (2 МБ × 5 файлов).
Дублируются в консоль с уровнем `INFO`. Буфер сбрасывается после
каждой записи — логи видны в реальном времени.

### Принципы

| Принцип | Описание |
|---------|----------|
| Работает — не трогаем | Работающий и читаемый код не переписывается |
| Логика важнее формы | Не разбиваем файлы ради метрик |
| Тесты — на логику | Покрытие бизнес-правил, не UI |
| Данные отделены от кода | Правила — в JSON |
| Единый стиль | SVG-иконки, тёмная тема |

## Известные ограничения

- **Только Windows.** Используются `win32print`, `win32com`,
  `os.startfile`, `DwmSetWindowAttribute`.
- **RDP-сессии не встраиваются в Core.** `mstsc.exe` — стороннее
  окно; Qt не поддерживает встраивание не-Qt окон. Единственный
  рабочий вариант — отдельное окно.
- **QtWebEngine 6.11.** Атрибут `WebAttribute.DownloadsEnabled`
  отсутствует, но скачивание работает через `downloadRequested`.
